# 智能体服务实现方案

> 本文遵循《医学专病知识库 ／ Agent ／ 测评平台开发规格说明》。旧版 SQLite、`sessions`​、Agent 内部向量检索和 `message/done` SSE 方案已废弃。

## 一、服务定位

​`medical-agent-api`​ 是独立 FastAPI 服务，开发端口 8002；`medical-agent-web` 是独立 Vue 3 应用，开发端口 5174。

Agent API 负责：

- LLM 调用和 Prompt/Skill 执行；
- ​`conversations`​ 与 `messages`；
- 多 MCP Client 和原子工具调用；
- ​`agent_runs`​、`tool_calls`​、`answer_citations`；
- REST 与 SSE；
- 无证据降级标记。

Evaluation API 负责跨步骤控制循环以及安全/治理策略。Agent API 提供可组合、可审计的原子能力。

## 二、强制架构规则

1. Agent 可以连接多个 MCP Server，包括 Knowledge MCP、`medical-mcp`、PubMed MCP 和其他受信任 MCP。
2. Agent 禁止连接 `knowledge_db`。
3. Agent 禁止维护第二套文献索引，禁止自行使用 Qdrant、向量库或 `vector_store.search()` 检索医学文献。
4. 所有 Knowledge 引用必须保存 `document_id`​、`document_version_id`​、`chunk_id`​、`evidence_span_id`​、`index_version`。
5. 外部 MCP 的原始参数、结果、稳定来源 ID 和结果哈希必须保存。
6. MCP 全部失败时允许模型回答，但必须显示“未经文献验证”，并且不得生成引用。

## 三、技术栈

- Python 3.12、FastAPI、Pydantic v2。
- PostgreSQL 16、SQLAlchemy 2、Alembic。
- MCP Python SDK。
- LLM SDK / OpenAI-compatible Client。
- SSE。
- structlog、pytest。
- Vue 3、TypeScript、Vite、Pinia、Element Plus。

数据库固定为独立 `agent_db`​。禁止把 SQLite 作为正式或默认实现，禁止以 `Base.metadata.create_all()` 替代 Alembic。

## 四、数据库模型

### `conversations`

对话生命周期和所有权：`id`​、`title`​、`user_id`​、`created_at`​、`updated_at`。

### `messages`

对话消息：`id`​、`conversation_id`​、`role`​、`content`​、`created_at`。

### `agent_runs`

一次问答或一次原子执行：`id`​、`conversation_id`​、`user_message_id`​、`model_provider`​、`model_name`​、`prompt_version`​、`skill_version`​、`status`​、`degraded_without_evidence`​、`started_at`​、`finished_at`。

### `tool_calls`

所有 MCP 调用：`id`​、`agent_run_id`​、`mcp_server`​、`tool_name`​、`arguments JSONB`​、`result JSONB`​、`result_hash`​、`latency_ms`​、`status`​、`created_at`。

### `answer_citations`

回答引用：`id`​、`message_id`​、`tool_call_id`​、`document_id`​、`document_version_id`​、`chunk_id`​、`evidence_span_id`​、`index_version`​、`citation_order`​、`source_server`​、`external_source_id`。

### `agent_skills`

Skill 版本：`id`​、`name`​、`version`​、`system_prompt`​、`config JSONB`​、`enabled`。

## 五、请求流程

```text
Agent Web / Evaluation API
  → 创建或选择 conversation
  → POST /chat 或 /chat/stream
  → 创建 agent_run
  → 根据环境变量选择模型和 MCP Servers
  → 并行/按策略执行 MCP 工具
  → 保存 tool_calls
  → 规范化证据并构建 Prompt
  → 调用 LLM
  → 保存 assistant message
  → 保存 answer_citations
  → 返回结果或 SSE 事件
```

Agent 只消费 MCP 返回的证据，不生成自己的文献检索索引。

## 六、REST API

- ​`POST /api/v1/conversations`
- ​`GET /api/v1/conversations`
- ​`GET /api/v1/conversations/{id}`
- ​`POST /api/v1/chat`
- ​`POST /api/v1/chat/stream`
- ​`GET /api/v1/runs/{id}`
- ​`GET /api/v1/runs/{id}/citations`
- ​`GET /api/v1/skills`
- ​`GET /health`

​`/chat`​ 请求使用 `conversation_id`​，首次会话通过 `/conversations`​ 显式创建。不得再引入 `/sessions` 作为同义资源。

## 七、SSE 事件

事件顺序按实际执行发送：

1. ​`run_started`
2. ​`tool_started`
3. ​`tool_completed`
4. ​`answer_delta`
5. ​`citations`
6. ​`run_completed`

异常发送 `run_failed`​。所有事件包含 `run_id`​；工具事件包含 `tool_call_id`​ 和 `mcp_server`；引用事件包含稳定 ID；完成事件包含模型、Prompt、Skill 版本和降级状态。

## 八、多 MCP 与引用

Knowledge MCP 是本项目结构化证据来源；外部 MCP 可补充 PubMed、药物、指南和其他证据。MCP Client 支持：

- 配置多个 Server；
- 启动时建立连接；
- 并行调用与独立超时；
- 明确工具映射，不使用“找不到就调用第一个工具”的不确定策略；
- 原始结果持久化；
- Server 级熔断和降级。

Knowledge 证据直接保留五个稳定 ID。外部证据不得伪造内部 ID；正式进入测评前需由 Knowledge API 注册证据快照并获得稳定 ID。

## 九、无证据降级

当全部 MCP 无有效证据时：

- 回答开头明确显示：“当前未检索到可核验文献证据，以下内容未经文献验证。”
- ​`answer_citations` 为空。
- ​`agent_runs.degraded_without_evidence = true`。
- ​`run_completed`​ 包含 `degraded_without_evidence: true`。
- Prompt 明确禁止模型编造文献、作者、DOI、PMID 或链接。

## 十、配置

配置全部来自环境变量，不使用 `model_configs` 数据库表，不提供模型密钥 CRUD：

- ​`DATABASE_URL`
- ​`MODEL_PROVIDER`
- ​`MODEL_NAME`
- ​`MODEL_BASE_URL`
- ​`MODEL_API_KEY`
- ​`MCP_SERVERS_JSON`
- ​`MAX_HISTORY_TURNS`
- ​`CONVERSATION_TTL_HOURS`
- ​`ALLOWED_ORIGINS`

模型或 MCP 配置变更通过修改部署环境变量并重启/滚动发布生效。

## 十一、独立仓库与启动

- Agent API：`http://localhost:8002`。
- Agent Web：`http://localhost:5174`。
- CORS 从 `ALLOWED_ORIGINS`​ 读取，开发值包含 `http://localhost:5174`。

API 仓库必须提供 Alembic、pytest、Dockerfile、compose.yaml、`.env.example` 和 README；Web 仓库独立提供 Vite 配置和 Dockerfile。

## 十二、测试要求

- Alembic 可从空数据库升级。
- Agent 不包含向量库依赖和本地检索实现。
- 多 MCP 并行、超时、部分失败和全部失败测试。
- 五个稳定 ID 的保存和返回测试。
- 外部证据原始结果与哈希回放测试。
- SSE 七种事件的契约测试。
- 无证据警告与禁止伪造引用测试。
- Evaluation 控制循环与 Agent 原子接口的集成测试。
