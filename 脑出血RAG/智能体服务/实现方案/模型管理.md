# 模型管理

‍

> 模型配置全部来自环境变量。旧版 `model_configs` 数据库表、模型 CRUD API、前端密钥管理和运行时写库切换方案已废弃。

## 一、设计原则

- 模型供应商、名称、端点和密钥全部由部署环境提供。
- 应用数据库不保存模型 API Key。
- 前端不读取、提交或修改密钥。
- 模型切换通过修改环境变量并重启或滚动发布完成。
- 每个 `agent_run` 记录实际使用的 provider、model、Prompt 版本和 Skill 版本。

## 二、环境变量

基础配置：

```text
MODEL_PROVIDER=deepseek
MODEL_NAME=deepseek-chat
MODEL_BASE_URL=https://api.deepseek.com
MODEL_API_KEY=...
MODEL_MAX_TOKENS=4096
MODEL_TEMPERATURE=0.2
```

如果需要预配置多个模型，使用单个 JSON 环境变量：

```text
MODEL_PROFILES_JSON={...}
DEFAULT_MODEL_PROFILE=deepseek
```

​`MODEL_PROFILES_JSON` 只由部署系统注入，不在仓库或数据库中持久化明文密钥。

## 三、配置加载与校验

应用启动时：

1. 使用 Pydantic Settings 读取环境变量。
2. 校验必填字段、URL、数值范围和默认 profile。
3. 为每个 profile 创建只读适配器配置。
4. 连接失败时 health/readiness 报告明确错误。
5. 运行期间不提供写配置接口。

## 四、模型选择

​`/chat`​ 可以接收一个受限的 `model_profile` 名称，但只能选择环境变量中已声明的 profile。调用方不能提交任意 Base URL 或 API Key。

没有指定时使用 `DEFAULT_MODEL_PROFILE`​。实际 profile、provider 和 model 写入 `agent_runs`。

## 五、API

允许提供只读接口：

- ​`GET /api/v1/models`：返回可用 profile 的非敏感元数据。
- ​`GET /api/v1/models/default`：返回默认 profile。
- ​`POST /api/v1/models/{profile}/test`：仅管理员可调用，用于连通性测试。

禁止提供创建、修改、删除模型或上传 API Key 的接口。返回结构不得包含密钥或环境变量原文。

## 六、适配器

统一 `ModelAdapter` 接口：

- ​`chat(prompt, conversation_id, run_id)`
- ​`stream(prompt, conversation_id, run_id)`

适配器根据只读环境配置创建。OpenAI-compatible、DeepSeek 等适配器不得在数据库中反查密钥。

## 七、安全

- ​`.env`​ 不提交，只提交 `.env.example`。
- 生产密钥由容器 Secret、CI/CD Secret 或密钥管理服务注入。
- 日志、异常、health 和只读模型接口都不得返回密钥。
- 模型测试结果限制长度，避免泄露 Prompt 或敏感数据。

## 八、数据库关系

不创建 `model_configs`​ 表。数据库只在 `agent_runs` 中保存本次执行使用的非敏感模型标识和版本信息，用于审计与回放。

## 九、部署变更

模型变更流程：更新部署环境变量 → 校验配置 → 滚动发布 → 调用只读测试接口 → 观察 readiness 和审计日志。
