# 配置文件管理

## 一、统一原则

项目配置全部来自环境变量。数据库用于业务数据和运行记录，不承担配置中心职责。

仓库只提交 `.env.example`​；本地 `.env`、生产 Secret 和 API Key 不提交到 Git。

## 二、Agent API 环境变量

### 数据库

- ​`DATABASE_URL`​：指向独立 PostgreSQL `agent_db`。

### 服务

- ​`APP_ENV`
- ​`APP_HOST`
- ​`APP_PORT=8002`
- ​`LOG_LEVEL`
- ​`ALLOWED_ORIGINS=http://localhost:5174`

### 模型

- ​`MODEL_PROVIDER`
- ​`MODEL_NAME`
- ​`MODEL_BASE_URL`
- ​`MODEL_API_KEY`
- ​`MODEL_MAX_TOKENS`
- ​`MODEL_TEMPERATURE`
- ​`MODEL_PROFILES_JSON`（可选，多模型）
- ​`DEFAULT_MODEL_PROFILE`（可选）

### MCP

- ​`MCP_SERVERS_JSON`：多个 MCP Server 的连接、工具白名单、超时和信任级别。

### 会话

- ​`MAX_HISTORY_TURNS`
- ​`CONVERSATION_TTL_HOURS`

### 运行时

- ​`WORKSPACE_ROOT`
- ​`REQUEST_TIMEOUT_SECONDS`

## 三、Pydantic Settings

​`Settings` 在启动阶段完成：

- 环境变量读取；
- 类型转换；
- 必填校验；
- URL、端口、数值范围和 JSON Schema 校验；
- 生产环境默认值安全检查。

配置错误应使 readiness 失败并给出不含密钥的诊断信息，不应静默回退到 SQLite 或不安全默认值。

## 四、禁止项

- 不创建 `model_configs`​ 或 `system_settings` 来保存运行配置。
- 不把 API Key 加密后存入业务数据库。
- 不提供写配置 REST API。
- 不允许前端提交 Base URL 或 API Key。
- 不在代码中硬编码 8000、5173、模型名或 MCP Server。
- 不使用 SQLite 作为 PostgreSQL 的静默降级。

## 五、多环境

开发、测试、预发布、生产使用同一套变量名，由部署系统提供不同值。测试环境使用独立 PostgreSQL 数据库或临时容器，迁移仍通过 Alembic。

## 六、密钥管理

生产环境通过 Docker/Kubernetes Secret、CI/CD Secret 或专用密钥管理服务注入。日志、异常、审计、health 和 API 响应不得输出密钥。

## 七、配置变更

修改环境变量后通过重启或滚动发布生效。发布流程应包含：

1. 配置 Schema 校验。
2. Alembic migration 检查。
3. 模型连通性检查。
4. MCP Server 连通性检查。
5. readiness 验证。

## 八、`.env.example` 示例

```text
APP_ENV=development
APP_HOST=0.0.0.0
APP_PORT=8002
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/agent_db
ALLOWED_ORIGINS=http://localhost:5174

MODEL_PROVIDER=deepseek
MODEL_NAME=deepseek-chat
MODEL_BASE_URL=https://api.deepseek.com
MODEL_API_KEY=
MODEL_MAX_TOKENS=4096
MODEL_TEMPERATURE=0.2

MCP_SERVERS_JSON=[]
MAX_HISTORY_TURNS=20
CONVERSATION_TTL_HOURS=24
WORKSPACE_ROOT=./runtime
REQUEST_TIMEOUT_SECONDS=120
```
